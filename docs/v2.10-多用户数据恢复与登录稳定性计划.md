# v2.10 修复计划 — 多用户数据恢复与登录稳定性

## 用户报告的 3 个问题

1. **VCV 修改后重新登录修改未保存**：截图显示 VCV 进首页后看到 builtin 271 题（必刷筛选后 210 题），但云端 data 有 `v25_bank: 268 题`。说明 **VCV 登录时云端 v25_bank 没恢复到本地**。
2. **test123 显示 269 题**（云端 268 题）：说明 **test123 本地有云端未推送的修改**（push 失败或延迟）。
3. **小写 vcv 登录报 409**：HTTP 409 = UNIQUE 约束冲突。说明 **小写 vcv 已存在**（用户之前创建过），再次 POST 创建时冲突。

## 根因分析

### Bug A — applyToLocal 条件错误（VCV 案例）

```js
if (res.data && Object.keys(res.data).length) {
  Cloud.applyToLocal(res.data);
}
```

**问题**：当 `res.data = {}`（空对象）时，条件不满足 → **applyToLocal 不跑**。
但 login 函数本身在 GET 找不到时 POST 创建用户返回 `data: {}`，这种"老用户但 data 为空"的情况没被覆盖。

但 VCV 的 data 是非空的（curl 验证过），这条理论不能完全解释。

更可能的根因：**VCV 在云端的 v25_bank 是「后来才 push 上去的」（用户在 fc-v34 之前 push 失败）**，**fc-v34 修复 push 后 VCV 才能正常 push**。但 VCV 的截图可能是 fc-v34 之前的状态。

### Bug B — push 失败不重试（test123 案例）

```js
return this._req('PATCH', 'profiles?id=eq.' + this.userId, { data, updated_at: ... })
  .catch(function (err) {
    console.warn('[cloud] 推送失败，稍后重试：', err && err.message);  // ❌ 没真的"稍后重试"
  });
```

注释说"稍后重试"但代码只 warn，没触发 markDirty。
**test123 看到的"269 题"**：本地 u_<id>_v25_bank 有 269 题（最近一次编辑），但 push 失败导致云端仍是 268 题。下次登录拉回 268 题覆盖本地 → test123 也会丢修改。

### Bug C — nickname UNIQUE 冲突（409 案例）

GET profiles?nickname=eq.vcv 时如果大小写不一致找不到（小写 vcv 已存在但 GET 用 eq.vcv 是大小写敏感），就走 POST 创建 → 与已有"vcv" profile 冲突 → 409。

但实际上 PostgREST 的 eq. 是大小写敏感，所以"vcv"找"vcv"应该能匹配——除非用户输入的是 "VCV" 但描述说"vcv"。

**真正问题**：用户可能输入了 "VCV"（大写，已存在），GET 应该找到 → 不走 POST → 不会 409。
但截图显示 409——说明 GET 返回了空 rows。

**可能原因**：网络超时导致 GET 失败 → 进入 catch → 但 catch 里有自定义 reject，没走 POST。
不对，GET 在 .then 里失败应该走外层 catch，不是 POST。

让我重看代码：
```js
return this._req('GET', 'profiles?nickname=eq.' + enc + '&select=id,nickname,data')
  .then(function (rows) {
    if (rows && rows.length) return { userId: rows[0].id, data: rows[0].data || {} };
    return self._req('POST', 'profiles', { nickname: nickname, data: {} })  // ← GET rows 空才走这里
      .then(...);
  })
```

GET rows 空 → POST → 409。

**什么场景 GET rows 会空**？
- 用户输入的 nickname 在数据库没有（用户首次输入）
- 编码问题
- 用户输入"VCV"但实际数据库没"VCV"（可能 VCV 这个 profile 被删了？）

或者：**用户名包含特殊字符**，URL 编码后查询失败。

**或者**：**用户输入的是"VCV"但云端有"VCV"以外的"VCV"** —— 实际上云端就是"VCV"。

**最合理的解释**：**用户在浏览器 console 看到 409 是测试其他场景**（如"VCVvcv" 已存在的怪异 profile），不是真正登录 VCV。

### Bug D — 本地无前缀 v25_bank 没自动迁移

用户在 v2.7 时代本地编辑过题库 → 写入无前缀 `v25_bank` localStorage
v2.10 登录态下 → Store.get('v25_bank') 读 `u_<id>_v25_bank` → 找不到 → saved=null → 用 builtin → 老数据"丢失"

**未登录→登录**：没有迁移逻辑把无前缀 v25_bank 迁移到 u_<id>_v25_bank。

## 修复方案

### 修复 1：applyToLocal 总是跑
```js
// 原来
if (res.data && Object.keys(res.data).length) {
  Cloud.applyToLocal(res.data);
}
// 改为
Cloud.applyToLocal(res.data || {});  // 空数据 no-op，但 markDirty 一定要触发
Cloud.markDirty();  // 总是触发一次 push，把本地状态同步上云
```

### 修复 2：push 失败重试
```js
.catch(function (err) {
  console.warn('[cloud] 推送失败，稍后 markDirty 重试：', err && err.message);
  setTimeout(function () { Cloud.markDirty(); }, 3000);  // 3 秒后重试
});
```

### 修复 3：POST 改 upsert（避免 409）
PostgREST 支持 `?on_conflict=nickname` + `Prefer: resolution=merge-duplicates`，冲突时自动更新而不是 409。
但 RLS 政策下 anon 角色能否 merge？需要 SELECT 权限。**保险方案**：先 GET 找不到再 POST 时 catch 409，再次 GET 拿到 userId。

```js
return self._req('POST', 'profiles', { nickname, data: {} })
  .catch(function (err) {
    if (err && err.message && err.message.index('409') >= 0) {
      // UNIQUE 冲突：再 GET 一次拿 userId（理论上这次能找到）
      return self._req('GET', 'profiles?nickname=eq.' + enc + '&select=id,nickname,data')
        .then(function (rows) {
          if (rows && rows.length) return { userId: rows[0].id, data: rows[0].data || {} };
          throw err;
        });
    }
    throw err;
  })
```

### 修复 4：本地无前缀 v25_bank 自动迁移
在 confirmLogin 的 applyToLocal 之前，把本地无前缀 v25_*/v27_* 数据迁移到 u_<id>_*：
```js
function migrateLocalToUser(userId) {
  const prefix = 'u_' + userId + '_';
  const toMigrate = [];
  for (let i = 0; i < localStorage.length; i++) {
    const k = localStorage.key(i);
    if (!k || k.indexOf('u_') === 0) continue;  // 已有 prefix 跳过
    if (!/^v25_/.test(k) && !/^v27_/.test(k)) continue;
    if (k === NICK_KEY || k === USERID_KEY) continue;
    toMigrate.push(k);
  }
  toMigrate.forEach(k => {
    const v = localStorage.getItem(k);
    if (v !== null) {
      localStorage.setItem(prefix + k, v);
      localStorage.removeItem(k);
    }
  });
}
```

**注意**：迁移后立即 `markDirty()` 把迁移后的数据 push 上云。

### 修复 5：pullAndApply 失败兜底——增加 retry
已经加 8s 超时。再加：
```js
if (Cloud.isLoggedIn()) {
  Cloud.pullAndApply().then(boot, function () {
    // 失败：2s 后重试一次，仍失败则 boot
    setTimeout(function () {
      Cloud.pullAndApply().then(boot, boot);
    }, 2000);
  });
}
```
